# Data Entry Form Example

Complex registration form with multi-field validation and conditional logic.

## Pattern: Form Validation

This example demonstrates:
- Required field validation
- Email format validation
- Min/max constraints
- Cross-field validation (password match)
- Checkbox validation (terms)
- Form-level submit button enabling
- Multiple input types (email, password, spin box, dropdown, checkbox)

## JSON Spec

The `data_entry_form.json` shows validation rules integrated at widget level:

```json
{
  "type": "email_field",
  "id": "email_field",
  "validation": [
    { "rule": "required", "message": "Email required" },
    { "rule": "email", "message": "Invalid email format" }
  ]
}
```

Each field has:
- Validation rules (required, email, min_length, range, custom)
- Error messages (shown on validation failure)
- Dependencies (password confirm depends on password)

## Implementation in simple_vision

### Create Form

```eiffel
form := sv.form
  .add_field (sv.field ("email")
    .widget (sv.email_field)
    .required
    .error_message ("Valid email required"))
  .add_field (sv.field ("password")
    .widget (sv.password_field)
    .required
    .min_length (8))
  .add_field (sv.field ("password_confirm")
    .widget (sv.password_field)
    .required
    .custom_validation (agent passwords_match))
  .add_field (sv.field ("age")
    .widget (sv.spin_box_range (18, 120))
    .required
    .range (18, 120))
  .on_valid (agent handle_submit)
```

### Validate Fields

```eiffel
passwords_match: BOOLEAN
  do
    Result := password_field.value ~ password_confirm_field.value
  end
```

### Handle Submit

```eiffel
handle_submit
  do
    if form.is_valid then
      api.register (
        email_field.value,
        password_field.value,
        age_field.value,
        country_field.value)
    else
      show_error_summary (form.errors)
    end
  end
```

## Key Patterns

1. **Field-Level Validation**: Each field validates independently
2. **Cross-Field Validation**: Password confirm checks against password field
3. **Form-Level Validation**: Submit button enabled only when all fields valid
4. **Error Messages**: Specific error text per validation rule
5. **Masked Inputs**: Email field auto-formats and validates email pattern

## Validation Rules Used

- `required` - Field cannot be empty
- `email` - Must be valid email format
- `min_length` - Minimum string length
- `range` - Numeric value within bounds
- `custom` - Custom function (password match)
